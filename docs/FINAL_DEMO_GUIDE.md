- PR-AUC / ROC-AUC

### Short Script

> Our Credit Stress module uses Logistic Regression. The target is a rule-based financial-stress proxy, so we intentionally exclude variables that directly construct that target. We use only Age, Dependents, Occupation, City Tier and Desired Savings Percentage in the strict benchmark. The tuned threshold is 0.68.

### Important Limitation

State clearly:

> This is not an actual credit-default model and it is never used to approve or reject a credit card.

# Viva Quick Questions

## Why did you use PR-AUC?

Because the positive classes are imbalanced, and PR-AUC focuses more directly on minority-class ranking quality than accuracy.

## Why is Credit Stress not a credit-default model?

Because its target is a rule-based financial-stress proxy, not observed repayment default.

## Why is Loan Risk experimental?

Because the positive class is rare, temporal coverage is limited and the final model's rare-event performance is not strong enough for real lending use.

## Why use Flask?

Flask is lightweight, easy to integrate with Python ML pipelines, supports sessions/APIs, and is suitable for a portfolio backend.

## Why support SQLite and MySQL?

SQLite makes demos easy, while MySQL demonstrates a more traditional multi-user relational backend option.
